# 美术、自主建模与资产制作

版本：0.1。本文规定制作目标，不表示模型或动画已经完成。

## 视觉方向

采用保留人体比例和材质层次的风格化 3D：人物结构可信，布料、皮肤和肤色金属清楚区分；建筑形状有设计感，远景细节简化。轮廓与战斗可读性优先，克制泛光和屏幕震动。

所有主角、敌人、建筑套件、重要道具由本项目自主建模。可使用程序化建模辅助重复结构，但交付应有可编辑源文件、可审阅模型和运行资产；程序中的基础几何占位不能作为正式人物验收。

## Oinja 外观不可丢失的结构

依据原项目当前 LOCK、canon.yaml 和批准四视图：

- 成年男性，正常人体比例，约 176 厘米，暖蜂蜜肤色；精瘦有肌，黑紫服装。
- 完整机械右臂、紫色右肩甲；金属接近肤色，以接缝、板片和反光区别有机皮肤。
- 左臂为有机臂，左前臂外侧有分叉网纹；左肩两片黑色柔软护甲，紫肘带位置和露肤间隔正确。
- 高帽冠的深紫针织帽、帽沿外短卷发；帽前略偏角色左侧一颗心，背面不补画帽心。
- 面罩连续覆盖鼻、嘴、下巴和全颈，收进领内。
- 两层紫腰带、右前髋一个 D 环及垂带；短裤无侧袋。
- 两只袜子的外侧各一颗心；不为背视角可见而移动到后面。
- B7 软布包从角色左肩斜向右后腰，浅薄贴背；上方魔术贴翻盖、下方两个翻盖袋，包面符文是平面装饰。
- 不对批准图进行镜像来生成另一侧，不覆盖原项目中的批准资产。

第三人称检视必须包含背部与两侧。背包、机械右臂和左臂符文的结构，不能仅靠正面宣传图验收。

## 自主建模流程

1. 以批准四视图建立比例与轮廓参考；原项目已有展示模型可只读参考。
2. 重新组织游戏网格、UV、关节变形和材质，保留核心服装与标记。
3. 制作骨骼、蒙皮和动作，检查肩肘、膝盖、包带与面罩的变形。
4. 制作右臂钩爪、圆盾、炮三形态，稳定连接到同一机械臂骨骼及挂点。
5. 将建模源文件和生成脚本留在本项目，再导出 GLB，优化并在游戏运行环境检查。
6. 依据真实镜头距离调整细节密度。远处看不见的纹理优先简化，但不可删除身份结构。

现有 Oinja/models 的说明明确缺少游戏骨骼、低模重拓扑和烘焙贴图，不能直接把那个展示工程列为已完成的游戏模型。

## 首版资产清单

| 类别 | 必须制作的内容 |
|---|---|
| Oinja | 基础角色；同一右臂下的钩爪、护盾、炮组件；左臂施法挂点；基础材质与一套奖励材质变体 |
| 五类敌人 | 五套独立轮廓与行为动画；精英参数及材质变体；织网主机专用加强组件 |

| 新港建筑 | 货柜塔与转运架、转运大厅、储能舱、冷却庭、管廊与维护塔、调度楼与工业中庭 |
| 共用设施 | 门、坡道、楼梯、护栏、脚手架、锚点、线缆、路灯、管道、系缆柱、标识、可破坏箱罐 |

| 战斗组件 | 经验、修复件、炮弹、电泡、网线节点、可反射子弹 |

每图至少六组主要建筑身份，正式模型应有入口、结构厚度、屋顶、台阶和工作设施。重复模块通过布局、尺度、连接与局部道具形成不同空间，不仅更换颜色。

## 动画

Oinja 至少覆盖：待机、前后左右移动、起跳与落地、普通拳击、重击、电泡、大电泡、钩爪发射／牵引、盾展开／移动／收回、炮变形／射击／恢复、雷电施放、雷雾投掷／回闪、屏障引导／完成／取消、受击、死亡与胜利。

动画可分层组合，技能命中由模拟事件驱动，不依赖渲染帧数。脚部滑动、武器穿身、背包大幅穿模和左右臂反转是需要修正的问题。

每类敌人至少有移动、攻击预备、攻击、恢复、受击和失效状态；悬浮与履带运动有对应动作。终局主机使用原织网机动作语言，加大阶段变化和核心暴露反馈。

## 特效与声音

- 玩家紫色电弧要能辨认起点、目标与连锁折转。屏障为角色直接施放的穹顶，强化传到机械右臂有短而清晰的能量反馈。
- 钩爪显示分节索与真实锚点。盾有实体厚度和接触反馈。炮的弹道、命中与后坐三者时间一致。
- 雷雾让敌人视线受限，但玩家能看清自己的轮廓、危险地面与有效回闪点。
- 敌方危险以暖色预警、轮廓和动作配合；不单靠红绿区别。近身包围、冲锋、齐射和网线分别有声音提示。
- 背景声包含海风、港机、结构声与不同建筑室内混响；电击、机械形变、命中和回复音分层。
- 使用自制或有明确许可的音源；来源写入资产清单。首版音乐可由自制节奏与环境层构成，不依赖未经授权的第三方歌曲。
- 音频在用户开始操作后启用，提供音乐、效果和主音量；关闭音频不丢失关键信息。

## 资产格式与预算

以下为初始生产预算，超出时先测量再决定，不把预算当成实测结果。

| 资产 | 初始预算 |
|---|---|
| 主角 LOD0 | 约 18k–30k 三角面，约 60 个骨骼以内，4 个主要材质组 |
| 主角 LOD1 | 约 8k–12k 三角面，核心外观标记保留 |
| 爬机 | 约 600–1000 三角面；远处进一步降级 |
| 其他普通敌人 | 每种 LOD0 约 2k–5k 三角面 |
| 主机 | 约 8k–15k 三角面，重用织网机结构与材质 |
| 主角贴图 | 主要贴图不超过 2K；共享衣装材质图集 |
| 环境贴图 | 通常 1K–2K，可复用平铺与图集 |
| 初次菜单加载 | 目标压缩传输不超过 8 MB |
| 首张选定地图及战斗共享资产 | 在菜单之后增量加载目标不超过 30 MB |
| 两图完整下载 | 目标不超过 70 MB；第二图按需加载 |

运行时统一 GLB／glTF 2.0。单位为米，脚底为角色原点，运行时 Y 向上，角色局部正前为 −Z。Blender 到 glTF 的坐标转换在导出端完成，避免在各加载器里增加不同补丁。

每个模型需要清晰的名称、层级、变形原点、材质、碰撞代理和 LOD 策略。可交互门桥有单独运动部件与碰撞状态。游戏不使用每颗螺丝的网格做碰撞。

## 保存与溯源

约定后续目录：

- art/source/：角色、敌人、地图的 .blend 与自制音频源文件。
- art/references/：确有需要时复制的批准参考及来源记录。
- art/reviews/：转台、四向截图、动画检查与修改记录。
- tools/blender/：自主建模和导出脚本。
- public/assets/：浏览器加载的压缩 GLB、贴图、音频。
- public/assets/manifest.json：稳定 ID、相对路径、版本、哈希、来源、资产状态和许可。
- artifacts/：运行时截图、性能记录与验证结果。

所有目录都位于 Oinja-game 下，实施时按需建立。正式角色验收以原批准四视图和本游戏运行画面共同判断；游戏中的新资产不自动升级为原作 Canon。
