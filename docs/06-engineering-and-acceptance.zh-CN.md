# 工程架构、制作顺序与验收

版本：0.1。本文件保留制作时的工程设计基线与验收目标。运行代码、资产和测试现已建立；当前实现范围、已完成证据与待测项目请查看 [发布与验收记录](08-release-and-qa.zh-CN.md)。下文未验证的预算、目标与目录示意不代表全部已经交付。

## 技术选择

采用 **TypeScript＋Vite＋Three.js** 的独立 3D 浏览器项目，Rapier 负责角色与场景碰撞，GLB／glTF 负责运行资产，DOM 负责 HUD 和菜单。该项目没有既有 React 宿主，使用直接的场景与游戏循环便于控制大量单位更新。

选择依据：Game Studio 的 plain Three.js 路线；[Three.js 官方文档](https://threejs.org/docs/)、[Rapier 角色控制器](https://rapier.rs/docs/user_guides/javascript/character_controller/)和 [Vite 官方指南](https://vite.dev/guide/)。依赖的具体兼容版本在实施时核实并锁定，不预写未经验证的版本号。

渲染与游戏规则分开。Three.js 场景对象不作为生命、电量、冷却、敌人 AI 或存档的唯一状态来源。

## 模拟、渲染与大量敌人

- 模拟采用固定 60 Hz 更新，渲染独立插值。不同屏幕刷新率不能改变射速、冷却或 18 分钟上限。
- 短暂慢帧最多补有限模拟步；长时间失焦或明显挂起直接暂停，恢复时清楚提示，不在后台偷偷推进战斗。
- 敌人管理使用复用池和空间分区。普通近邻分离、目标查询、范围伤害不用全体两两遍历。
- 大量轻型敌人主要使用角色代理／查询和导航，不为每个肢体创建动态刚体。Rapier 处理世界几何与关键碰撞，模拟层决定生命和技能规则。
- 角色采用胶囊控制器；静态建筑采用简化碰撞，门桥等动态对象单独同步。钩爪和炮后坐进行路径扫掠，不能瞬移越过障碍。
- 导航采用分层可走区域与区域门户；上层、下层和坡道连接显式登记。门桥变化更新连接和碰撞；攻击视线另外检查，不能用“可导航”代替“可射击”。
- 场景按区域组织，重复建筑和敌人部件合批。远处动画降低更新频率，伤害判断与危险预警不降级。
- 爆炸、电弧、碎片、伤害数字均有视觉预算。预算满时优先保留危险预警、角色轮廓和真实命中反馈。
- 随机种子区分刷怪、升级与装饰。记录种子和输入用于复现；不承诺跨浏览器物理浮点逐位一致。

## 镜头与输入

高位跟随默认距离约 7.5 米，俯角约 30°，可用设置在舒适范围调整。角色后方障碍通过相机碰撞缩短距离；进入室内时平滑变化，不穿墙偷看。

浏览器通过明确的“开始”操作获取鼠标控制。Esc、失焦、升级、地图与设置打开时解除鼠标控制并暂停世界；回到游戏必须通过用户操作恢复。若鼠标锁定不可用，提供拖动视角的回退方式。

冲锋方向、回闪落点、屏障范围和钩爪锚点均具有世界内提示。手动技能抢占规则与右臂互斥以模拟状态机实现，不依赖动画是否看起来结束。

## HUD 与流程

主要常驻 HUD 合并为屏幕边缘的生命、电量、当前普攻、同调计数、技能冷却和经验条；角落附小型计时／目标提示。地图、图鉴和详细控制默认收起。中心与下中部尽量保持清晰，常驻 UI 目标低于画面约 20%。

完整状态：

1. 初始加载、加载失败与重试。
2. 标题、模式与地图选择、入门技能选择。
3. 可跳过的首局操作提示。
4. 战斗 HUD、拾取、技能不可用原因、事件提示。
5. 升级三选一、进化选择、重抽。
6. 暂停、地图、音量、键位与画质设置。
7. 死亡／通关／超时结算、解锁展示与重开。
8. 中断续局提示、存档恢复失败提示、图形环境不支持提示。

中文为首版文案，按钮和技能卡使用清晰层级。支持减弱动态效果、关闭震动与伤害数字；不同攻击类型也用形状和声音表达。电脑为已确认目标，小窗口做适配；不把手机触控纳入本阶段验收。

## 资产加载与保存

- 按菜单、共享战斗资产、选定地图分组加载；第二图按需读取。资产引用采用稳定 manifest ID。
- 加载失败显示具体资源类别并可重试；禁止因为个别模型缺失而用看不见的碰撞体继续战斗。
- GLB 输出前检查尺度、骨骼、动画、材质、碰撞标记和 LOD。压缩优先采用一套已验证流程，不盲目同时加入多种几何压缩。
- 本地设置和长期记录采用带版本的轻量存储；本局检查点采用可序列化数据。存档中不放 Three.js 或 Rapier 对象。
- 每 30 秒及升级后保存本局检查点，包含时间、地图／模式、随机状态、玩家、敌人、事件、成长选择与终局状态。升级菜单期间保存选项和未完成选择，恢复后不能免费重抽。
- 重新打开可选择恢复或放弃本局；恢复时暂停并有短准备倒计时。死亡／结算标记先完成，避免已结束本局被恢复。
- 两个标签页同时打开时提示并保护同一个存档，不能互相覆盖。存储失败可继续临时游玩，明确提示本次记录无法保存。
- 不要求账号、联网排行榜或云服务。开发阶段通过本地服务预览；产物可由静态站点承载。

## 性能目标与测量

初始参考档设为 M1／8 GB 级别笔记本、1920×1080 输出、中画质，实际记录测试设备与浏览器版本。该档不是已达成的性能声明。

- 目标常态约 60 FPS、终局高压仍能稳定游玩；验收记录平均帧时、P95 帧时与明显卡顿，P95 目标不高于 33.3 毫秒。
- 对 220 普通终局并发及加时 260 单位分别测试，敌人混合组成固定并记录。只跑空地图不能代表通过。
- CPU 模拟、GPU 渲染、纹理和几何占用分别记录；运行时估算 GPU 资产占用目标不超过约 512 MB。
- 低画质降低阴影、后处理、粒子和分辨率；不改变敌人伤害、预警时长或玩家碰撞。
- 地图切换、重开十次检查资源释放，不能持续积累几何、材质、音频或事件监听。
- 正式浏览器验收覆盖实施时的稳定版 Chrome 和 Safari；记录 WebGL 上下文丢失后的恢复或安全退出路径。
- 使用实际截图检查角色读法、建筑层次和特效遮挡。必要时用 GPU 分析工具定位帧成本，不能只根据代码推测性能。

## 制作关卡

| 阶段 | 产出 | 通过后才继续 |
|---|---|---|
| 0 设计确认 | 本文件包与共同理解确认 | 用户确认最终蓝图；后续常规细节由设计方自主处理 |
| 1 可玩骨架 | 镜头、移动、碰撞、自动普攻、钩爪＋雷电、爬机＋奔机、旧港局部灰盒 | 输入、命中、地形与暂停稳定，基础战斗能读懂 |
| 2 完整战斗 | 六技能、两模式、全部五敌人、成长、终局、结算 | 两模式战斗闭环与九种入门搭配的规则检查通过 |
| 3 双图空间 | 两张完整灰盒、六区域、多环路、事件与导航 | 不带钩爪可走全部必需路线；敌人可达；无死锁 |
| 4 正式美术 | 自主角色／敌人模型、双图建筑、动画、特效、声音与 HUD | 运行画面与动作检查通过，核心 Canon 视觉保持 |
| 5 平衡和性能 | 实际长局试玩、压力场景、资产优化、存档验证 | 下面的首版清单有证据，重要缺陷修复 |
| 6 交付 | 可运行构建、源工程、模型源文件、说明与报告 | 两图×两模式均验证，交付状态清楚 |

中间的灰盒和首个可玩版本用于验证，不替代用户要求的自主建模和丰富双地图。阶段验收以必要检查为主，发现失败先修复，不在未通过时宣称完成。

验证形式：纯规则单元测试覆盖结算、资源、升级池与时钟；集成检查覆盖物理和导航；浏览器自动化覆盖启动、菜单、加载、暂停与结算；截图和人工试玩覆盖 3D 画面与战斗体验。文档修改本身不制造镜像实现的测试。

至少保存两图×两模式各一次完整正常速度胜利记录，以及死亡、超时和意外中断恢复的证据。调试加速可以验证时刻与状态，不能替代正常速度的平衡试玩。九种入门组合先完成规则与压力检查，重点人工试玩输出、机动和防御三类代表搭配。

验收报告区分通过、失败、未验证；提供文件、截图、设备和复现条件。性能、平衡和视觉效果在实施完成前都保持为目标。
