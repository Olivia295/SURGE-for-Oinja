# Surge 视觉与渲染实现

记录日期：2026-09-18。此文记录实际渲染实现和独立检查，不代替整局玩法验收。

## 接口与边界

`src/surge/renderer.ts` 导出 `SurgeRenderer`，构造参数为 `canvas, settings`，提供：

- `load(progress)`：并行加载 Oinja、五类敌人及三种右臂挂件。
- `setWorld(world)`：接管地图显示；替换时释放旧地图。调用方先释放旧物理世界，不应再重复管理地图显示资源。
- `applySettings(settings)`、`resize()`、`clear()`、`render(state, dt)`、`dispose()`。
- 公开 `camera`、`scene`、`renderer`，供主线程投影和诊断使用。

只读取 RunState，不写生命、技能、敌人、时间或事件进度。`render(null, dt)` 为角色待机和地图预览。主线程负责输入、音频、暂停和图形上下文恢复提示。

## 镜头和人物

- 固定朝向高位斜俯第三人称，相机偏移比例约 `(0, .9, 1)`，不随角色转向，适配世界轴 WASD。
- 距离默认 26 米，可在 22–30 米范围设置。常规桌面横向视角约 64 度，默认目标平面的横向范围约 32.5 米。
- 指数平滑跟随；遮挡检测每约 90 毫秒执行，覆盖脚部、躯干、头部三个高度及左右三个位置。遮挡物平滑淡至原透明度的 16%，不通过突然缩短镜头距离解决遮挡。
- 原 Oinja GLB、材质、比例关系、右义肢、左符文与背包保持不变；战斗内整体显示比例为 1.3；菜单预览单独使用 2.0。五种原机械敌人继续使用现有 GLB。
- 保留载入的 17 条角色动画，按短动作选择普攻、施法、炮击、护盾等；单次动作显示上限约 0.34 秒。装备、场地法术、持续护盾不会让人物一直维持施法姿态。无输入且无新动作时回到待机，移动时回到跑步。
- 右臂挂件定位到 `R_hand` 世界坐标，朝角色当前朝向摆放；不依赖原骨骼局部轴方向。

## 原创机械支援

`src/surge/machines.ts` 为可复用程序建模源文件。各形态将静态部件按六类材质合批，实例共享几何和材质，不需要每帧重新建模。

| 形态 | 可识别结构 |
| --- | --- |
| 机械无人机 | 双涵道风扇、装甲机身、前向镜头、下置发射器、尾翼与天线 |
| 泰坦 | 宽肩双足、装甲胫骨、液压关节、大型工业拳套、胸部六角反应炉 |
| 治疗支援 | 白色救援舱、四瓣稳定器、绿色十字标记与环形供能结构 |
| 棱镜支援 | 纵向晶体、机械陀螺环、三个连接臂和节点 |

无人机的世界高度直接使用模拟层给出的 `Drone.pos`；地影使用地图地面高度。泰坦为落地形态。未制作这些新支援的独立 GLB，实际模型由上述源代码构建。

## 战斗可读性

- Oinja 使用紧贴脚底的金色定位圈；护盾偏青绿，同调偏紫金。圈体避免大面积遮住角色。
- 近战冲击是有朝向的扇形波，不用完整圆圈冒充方向。无方向字段时保留首次显示朝向，避免人物转身使旧冲击波跟随旋转。
- 电弧使用分段折线和较细的亮芯；投射物区分敌方橙红与玩家能力色，并配短尾迹。
- 冲锋敌人显示双边预警通道和前进箭头；枪手显示瞄准线；范围攻击显示地面范围。精英与终局敌人额外显示脚圈和生命条。
- 雾与危险区域主要采用低透明度地面填充、边缘圈和少量粒子，不用不透明圆柱遮挡战场。
- 设施可用状态显示细灯柱；进行中额外显示环形进度节点。设施文字和完整任务说明由 UI 提供。
- 同调开始产生向外扩展的紫金双环，持续阶段使用环绕能量点。震屏可关闭，减弱动态设置会抑制震屏、拾取上下浮动和部分闪动。
- 伤害数字最多同时显示 24 个，过期后移除；不维护长期战斗文字面板。

## 资源预算与清理

`src/surge/render-pool.ts` 使用固定容量 InstancedMesh，提供独立实例颜色和透明度。运行时写实例矩阵，不按每个电弧或冲击波创建、销毁网格。

| 池 | 容量 |
| --- | ---: |
| 投射物 | 1,500 |
| 经验 | 3,000 |
| 治疗标记部件 | 256 |
| 地影 | 450 |
| 圆环 / 区域填充 / 方向扇形 | 400 / 180 / 160 |
| 电弧与线段 | 2,600 |
| 粒子 | 1,600 |
| 设施灯柱 / 预警箭头 | 64 / 80 |

超过池容量仅省略额外视觉实例，不修改命中和模拟结果。敌人死亡播放短动画，最多保留 24 个离场模型；移除时停止动画、清除 mixer 对根节点的缓存并释放各克隆 Skeleton 的 boneTexture。共享模型几何仅在 renderer 最终销毁时释放。

地图遮挡材质使用专属副本；换图前还原原材质并销毁副本，再调用地图 dispose。`dispose()` 也移除窗口 resize 监听和伤害数字层，销毁实例池、程序模型、载入资产、阴影贴图及 WebGLRenderer。资源加载失败会等待同批请求结束，再清理成功加载的部分，允许再次尝试。

## 已执行检查

复现脚本和证据全部位于 `art/reviews/`：

- `surge-render-check.html`：隔离的渲染场景，直接接入新地图和模拟数据；不启动主游戏 UI。
- `surge-render-check.mjs`、`surge-render-validation.json`：五敌、四种机械支援、治疗与经验显示；零页面/控制台错误。
- `surge-render-game.png`：实际浏览器画面，1440×900。已读取截图检查人物、方向预警、支援轮廓和区域效果。
- 长施法测试：将 actionTime 保持为 3 秒，渲染 1 秒后 actionTime 仍为约 2 秒，人物已回到 idle，证明确实不会被持续计时锁住动作。
- 连续 6 次清理与重建：texture 每次从 30 回到 10，再回到 30；geometry 热身后稳定在 179，没有逐次增长。
- 全项目 TypeScript 检查在最终接口接入阶段通过。

`surge-render-pressure.mjs` / `surge-render-pressure.json` 为独立渲染压力检查：Apple M1 Max、ANGLE Metal、1440×900、DPR 1、中画质，220 个敌人、160 个特效、1,000 个经验物件。预热 2 秒后采样 4.5 秒，约 **60.0 FPS**，P95 帧时约 **16.8 ms**，1,791 次绘制、约 123 万三角面，零页面/控制台错误。

此压力场景未运行 AI、物理和完整 UI，因此不能据此承诺整局表现、其他硬件表现或主观战斗爽感。尚需在实际游戏中检查场景遮挡、密集攻击混合时的可读性和完整长局表现。

## 菜单构图补记

仅 `state === null` 时使用约 20 米、更低俯角的预览镜头，目标向左移动 5.6 米，让 Oinja 位于画面右侧；预览整体比例为 2.0，战斗内仍为 1.3。已查看 `artifacts/surge-runtime/menu-before-1440.png` 与 `menu-after-1440.png`，以及对应 1024 宽截图，人物不再位于左侧选择区边界。进入游戏后镜头坐标、FOV 和人物比例与修改前一致。

整合 AI、物理、HUD 和渲染的压力结果、三次重开及 WebGL 恢复证据详见 `artifacts/surge-runtime/README.md`；其中敌群分离、导航精确 AABB 段相交与存档/终局修复后的最终 260 敌采样约 60 FPS、P95 帧时 16.8ms、P95 模拟步 1.0ms、P95 CPU 渲染提交 9.1ms。环境为 Apple M1 Max、1920×1080、DPR 1、中画质；260 敌全程存活，无页面错误或失败资源。新版 JSON 保留 9 个源文件的 SHA-256，旧压力结果仅作基线归档，不与本轮最终数据混用。该测试采用明确记录的压力夹具，不代表正常长局平衡。

## 2026-09-19 移动与首次战斗卡顿修复

本轮以 45 秒普通移动和自然战斗采样定位问题，不用静态敌群替代移动检查。载入期间预编译角色、五敌、机械支援和所有彩色实例池；伤害数字复用 resize 时读取的画布矩形；人物与相机使用固定模拟步间的显示插值，跑步动画依据模拟步速度，模拟坐标本身不改变。攻击扇形读取独立 `FX.yaw`，不再依赖正在移动的人物朝向。菜单构图保持原有设置。

Apple M1 Max、1920×1080、DPR 1、中画质下，同条件 45 秒样本的平均帧率由 58.77 提升到 59.98 FPS，P95 均为 16.7 ms；超过 50 ms 的帧间隔由 4 次降为 0 次，最大间隔由 600.0 降为 33.3 ms。不能把全部改善归因于渲染：物理移动与攻击朝向也同期修复。WebGL 提交最大耗时由 85.2 降为 7.9 ms，伤害标签最大耗时由 32.4 降为 0.2 ms。自动保存未改动，基线保存耗时没有支持它是主要原因的证据。

9 项菜单/暂停/升级/续局与插值检查通过，新增可选联动存档字段的 2 项兼容性测试通过。普通移动、CPU 调用栈、源码哈希、截图、独立密集联动夹具和后续尖峰诊断详见 `artifacts/surge-movement/runtime-report.md`。前节 2026-09-18 的 260 敌结果是历史版本记录；本节移动样本与后续密集联动样本均独立记录版本，不能混作同一次验收。


密集联动随后发现的模拟尖峰已通过调用栈定位到冷却中重复索敌排序，并由模拟层优化。最终只复核原问题夹具：相同起止局内时间、相同联动次数/伤害/承伤，模拟步最大耗时 60.5 → 2.7 ms、P95 2.1 → 1.0 ms，最大帧间隔 66.7 → 16.8 ms，无大于 5 ms 的模拟步或页面错误。`synergy-profile-after-targets` 是这项最终证据；早期 profile 保留用于定位过程，不与最终结果混用。
