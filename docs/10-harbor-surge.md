# 旧港复流：密集地图交付

本文件描述新版 `src/surge/harbor.ts` 的实际地图实现。地图交互进度、敌人、奖励结算和存档由新版游戏运行模块负责。它不是原 Oinja 世界观的增补档案。

## 入口与规模

`createHarbor(seed: number): Promise<HarborResult>` 返回现有 `MapWorld` 接口和 12 个 `EventDefinition`。不加载旧版大地图，复用 `HarborKit` 的原创模块建模与材质合批能力。

- 可玩边界：X、Z 均为 −90 至 90 米。
- 出生：`[0, 0, 12]`，折线工坊中心广场。
- 地面高度 0，高架高度 5.5 米，检修渠底 −2.4 米。
- `seed` 只改变材质细节、道边物件颜色，不改变通行几何；玩法事件抽选由运行模块决定。
- 每个事件中心保留约 3 米无障碍空间。所有事件都能步行抵达，不要求特定技能。

## 路线与循环

中央南北轴、东西轴形成四向分流。X=−39、29 的内环支路连接南北横街；X=−74、76 的外环提供避让与侧向进场。店铺两端都有地面门洞，能把街面环路缩短为室内穿行。

高架位于 Z=−24，主桥从 X=−42 到 42。西坡道由 `[-70,0,-24]` 上至 `[-42,5.5,-24]`，东坡道由 `[42,5.5,-24]` 降至 `[70,0,-24]`。坡度约 11 度。桥面、桥下地面采用不同导航层，不会直接把地面敌人传上高架。

码头检修渠位于 X=56–65、Z=25–62。落桥连接 `[52,0,43]` 与 `[69,0,43]`；未落桥时仍能沿渠两端绕行。渠底有南北两条实际坡道，即使落入也能步行返回地面。

`world.openShortcut(id)` 启动设施动画。货门 1.6 秒升起，碰撞立即撤除；吊桥 3 秒落下，结束时启用桥面及护栏碰撞并更新导航。主循环必须在 `world.update(time,dt)` 之后调用 `physics.syncShortcuts()`。

`world.openShortcut(id,true)` 用于恢复完成事件：几何、碰撞与导航立即进入最终状态。重复调用安全，其他事件 ID 调用不改变地图。

## 视觉与性能

黄昏暖光、蓝紫阴影、红砖与橙色工业构件、青绿色设备线路。地面包含程序化铺砖/沥青纹理、交通标线、作业区、排水沟；道路旁加入路灯、货架、箱体、树池与长椅。海面、船只、灯塔与远处街区构成背景。

环境以米为单位、Y 轴向上。所有源几何都保留在 TypeScript 建模代码中，按区域和材质合批；不会为每盏路灯创建实时光源。屋顶、雨棚和独立合批的广场旗串记录在 `world.occluders`，供现有遮挡淡化使用。

最终统计由 `validateHarbor()` 返回。最初完成版本147 个合批网格、3.9 万三角形、203 个碰撞体和 21 个遮挡物；完整渲染帧的绘制次数还取决于阴影及主运行模块。

## Canon 使用边界

折线屋工坊、回栈场货运、第七码头、储电装置、有限供能与跨专业协作取自现行 Oinja 文字题材。本地图把这些题材压缩成可重复战斗区域；具体街道布局、12 个设施事件及协作奖励是游戏设计，不是原城市地理或叙事 Canon 的新结论。

## 最终整局与追兵复测

`tools/surge/map-balance.ts` 使用真实地图、Rapier 和 SurgeSimulation，以正常移动、闪避、同调、交互与已提供的选卡运行。危险等级 0、balanced 开局，固定 30 Hz 外部加速；不直接改写生命、经验、伤害、敌人或局内时间。默认及本轮显式指定的种子均为 `731,6000`。高层战术每 0.2 秒更新，方向每个物理步更新并按路点剩余距离限速；导航路径统一来自地图，移除了机器人原先宽松的独立抄近路判断。

```sh
SURGE_MAP_SEEDS=731,6000 ./node_modules/.bin/tsx tools/surge/map-balance.ts > artifacts/surge/map-balance.log
```

此前修复的路径问题包括：贴墙起点不能回退到墙另一侧；重规划不能返回已经走过的起点节点；必须保留绕墙拐点；坡面侧边不能被宽松高度容差误认为可上台阶。模拟层同时修复跨层目标寻路、交互高度，以及守卫事件的地点计数。

本轮额外保留并修复了真实护送失败：旧导航每 0.8m 采样一次，漏过箱体 `world-72` 扩张角的一小段相交；护送车每 0.1m 检查实际位置，因而停在 `[-66.32406532108263,0,-36.582329919475654]`。`world-navigation.ts` 现对实体增加精确膨胀 AABB 线段检测，同时保留上下层与坡面高度检查。独立回归夹具沿用正式 `Physics.route`、`valid`、`floor` 与 0.1m 步长，到原目标耗时 **3.93 秒**，到当时重试目标 **8.40 秒**，两者阻塞帧均为 0。码头转角的真实 Rapier 角色检查也通过；原来的 22 项实体路线在修复后再次全部通过。

`map-balance-before-bot-fix.json` 保留发现问题时的 731 种子旧结果；`map-balance-old-probe.log` 保留护送车坐标、目标和不再增长的进度。两个原先被怀疑的玩家停留坐标在独立直接行走中可达，不能单凭其四舍五入坐标断言有实体封路；实际护送车失败坐标另由 `map-corner-probe.json` 严格复现并验证修复。

最终机器人仍有避让与绕角恢复迟缓，日志的最长低位移段为 **48.00 秒**（drone / 6000），该局于 165.77 秒完成六事件。这个指标不能解释为真人必然卡住，也不能宣称已完全消除所有绕角停顿。原 chain / 731 现于 66.57 秒完成六事件，最长低位移段 2.13 秒。

当前危险等级 0 下，机器人完成构筑后的首领约在出现后 1.20–19.43 秒死亡，部分局没有扣除生命；后续真人难度与首领体验仍需评估，不能只用通关数证明平衡优秀。
